# Languages and internationalization

Registry fields: BCP 47 code, native display name (endonym), stable sort key, searchable aliases, direction, translation status. Keep `system` first, ordinary choices sorted by a fixed ASCII sort key independent of the current locale. Avoid flags: language is not nationality. Show a checkmark for the committed choice and a distinct active keyboard marker. Search normalizes Unicode/case and diacritics, supports code/native/English name plus product-relevant aliases. Do not promise transliteration or translation-based search unless actually implemented. Announce no results and allow query clearing.

Persist the choice, not just its current resolution. Resolve system preferences in order: exact supported tag, supported script/region family, base language, then English. Do not collapse explicit Traditional Chinese into Simplified Chinese: if the product has no compatible Traditional translation, continue to another preference or English. A persisted locale removed from the registry needs an explicit compatibility migration, or system fallback with a notice. Refresh system resolution on languagechange/resume. Missing message keys fall back to the source English sentence, never a raw key in production.

Recommended starting registry for this author's products: English and Simplified Chinese; add Traditional Chinese regional variants when translations are maintained, then languages justified by actual audiences. The PathBlender source has 43 registered choices, including ar/he RTL and Chinese/English regional variants; that is an observed product configuration, not a required LYT language count or certification of translation quality. `allowed/configurable` does not mean `translated`, `reviewed` or `shipped`.

The reference offers English, 简体中文 and العربية (Arabic) as AI-authored demonstration dictionaries, plus an English long-text pseudo locale. Arabic is a layout/testing demonstration and is clearly labeled unreviewed. None has received a native-speaker editorial audit. Pseudo text is never selected by automatic system matching. The dictionary-key parity check proves presence, not linguistic accuracy. A shipping product should hide incomplete locales from its normal picker or explicitly label them as preview.

## Content and layout

Translate complete sentences, including accessibility names, error recovery, tooltips, status and empty results. Don't concatenate fragments to build grammar. Use ICU/MessageFormat or platform plural rules (`Intl.PluralRules` for the reference), with all categories a locale needs. Format numbers/dates via locale APIs; preserve machine-readable serialized values separately. The reference includes localized dates, counts and Arabic plural categories. Long-text pseudo localization is for expansion testing, not a genuine language.

Set document/component language and direction. Use logical inline-start/end and block spacing; mirror directional navigation icons but not media playback, logos or data geometry. Isolate unknown user strings with `bdi dir=auto`; isolate versions, IDs and code with `bdi dir=ltr`. Align and order via logical direction, not manual string reversal. Allow CJK wrapping and larger text; avoid ellipsis for errors and choice labels. Inputs keep focus and composition during locale changes. Theme/locale changes update labels in place and never reset drafts, selection or active work.

Desktop reference: searchable anchored dialog. Narrow web: selection sheet with close and scroll; native mobile: platform page/sheet with Back, safe area, Dynamic Type/font scale and keyboard avoidance. Test native translation on actual devices before claiming support. A responsive web screenshot proves only responsive web behavior.
